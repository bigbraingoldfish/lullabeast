## [Unreleased]

### Added

- **P1 Stage F — Reachability advisory (COMPLETE-phase only).** Executor gate now runs a static import-graph walk from `verification.entry_point.command` after every blocking check has passed, and surfaces a single summarising `reachability_warning` pipeline event per phase when manifest files cannot be reached from the entry point. Advisory only — never fails the phase; the gate exit code is unchanged. **Scoped to `COMPLETE-*` phases**: reachability-from-entry is a whole-artifact property, and running it per phase would misclassify the routine add-then-wire roadmap pattern (e.g. `DATA-E1` adds a localStorage utility; `DATA-E2` wires it in a later phase) as orphan code. Warning copy is hedged accordingly ("declared in manifest but not reached from entry point — orphan, or wiring landed in a different entry's path"); the UI summary reads *"N file(s) not reached from entry — a.py, b.py, c.py. Confirm intent: orphan vs. wiring landed elsewhere."*

  *Resolver coverage:* Python (`python`, `python -m`, `uvicorn`, `flask`, `gunicorn`, `hypercorn`) via `ast` parsing; JS/TS (`node`, `npm`, `vite`, `tsx`, `ts-node`, `yarn`, `pnpm`, plus `npx <tool>` which strips the wrapper before classification) via pure-Python regex parsing. Other languages emit a single `no_resolver` warning. Test-runner entries (`pytest`, `jest`, `vitest`, `playwright`, `cypress`, `mocha`, `unittest`) emit a distinct `reachability_not_applicable` event so visibility is preserved without polluting the warning channel.

  *Two-channel artifact pattern:* advisory gate output is written to a new `executor_advisory_detail.json`, separate from the existing `executor_gate_detail.json` (which remains the failure-detail channel consumed by `write_failure_context` for executor self-heal). The orchestrator's new `Orchestrator._emit_reachability_advisory(raw_id)` drains the advisory file on the executor PASS path, emits one summarising `reachability_warning` event + one `reachability_not_applicable` event when set + one event per diagnostic, then removes the file. Future advisory checks extend the advisory file's envelope rather than co-tenanting in the failure file. Promotion of reachability to a blocking (and per-phase) gate is **P3 Stage A**, gated on resolver coverage matching the demo project mix, measured false-positive rate < 10%, and a `pure_library: true` suppression mechanism for the add-then-wire false-positive class.

  *Added (new files):* `autodev/pipeline/gate_scripts/reachability/__init__.py`, `registry.py`, `python.py`, `js_ts.py` (co-located with `utils.py` so the existing gate sibling-import mechanism applies — no second `sys.path` hack). UI rendering in `ui/index.html`: `reachability_warning` events get a yellow badge, `reachability_not_applicable` get a slate badge, both distinct from failures (red), gate diagnostics (purple), and `gate_fail` (amber). Documentation in `autodev/docs/PIPELINE-SPEC.md` §4 (Reachability Advisory subsection) + new §4.5 (Advisory Checks vs Blocking Gates pattern + promotion criteria) + event-catalogue rows; `CLAUDE.md` event-catalogue rows + Gate Script Interface Contract advisory-channel paragraph.

  *Changed:* `phase_resolver.py` now parses `verification.md`'s `## Entry point` section into a structured `entry_point: {command, ready_signal}` dict written onto `current_phase.json` — additive field; pre-existing consumers ignore unknown keys. **Each bullet parses independently** (departs from `_extract_behavioral_verification`'s all-or-nothing rule because reachability needs only `command`; coupling it to `ready_signal` would silently disable the check whenever the unrelated field was absent). `executor_gate.py` gains `_check_reachability_advisory`, `_write_advisory_detail`, and `_clear_advisory_detail` helpers; the existing `_clear_executor_gate_detail()` on the PASS path stays untouched — the new advisory file is on its own channel. `orchestrator.py` adds `executor_advisory_detail.json` to all four per-phase artifact cleanup lists (`reset_phase`, `reset_execution`, `write_failure_context`, the trailing reset path).

  *Tests (TDD, written first, all green):* 75 new tests across `autodev/tests/test_reachability_python.py` (8 tests), `test_reachability_js_ts.py` (8), `test_reachability_unsupported_language.py` (17), `test_phase_resolver_entry_point.py` (7), `test_executor_gate_reachability_advisory.py` (10), `test_orchestrator_reachability_events.py` (7), and `tests/test_ui_reachability_warning_rendering.py` (9). The load-bearing scoping guard is `test_non_complete_phase_skips_check_entirely` — it pins the design decision that prevents per-phase cry-wolf and would catch any future regression that drops the COMPLETE-prefix gate. ### Fixed

- **Ideas chat reply stranded on disk when `turns/{n}.done` never landed → "Working…" forever, even after a refresh.** Observed live (Balloon Popping Game, session-24): the agent wrote the reply (`turns/24.md`) but the `.done` sentinel never landed (interrupted run), and `turns/25.md` appeared too. The completion contract hinged entirely on `.done`, so the held POST waited the full 900 s backstop and `GET /session` left the placeholder `pending` indefinitely — the reply was invisible *even on refresh* (the reconciliation required `.done`). Fix (`ui/server.py`): new `_ideas_stranded_md_reply(idea_dir, turn, attempt_start, quiet_secs)` surfaces a fresh `turns/{n}.md` when `.done` is absent **and** the activity stamp has been silent for `quiet_secs` (the agent has demonstrably stopped, so the `.md` is final). The stamp-silence gate is essential — during a normal turn the agent writes the chat `.md` first, then runs a (possibly ~2 min silent) PRD-draft model call, then writes `.done` last; gating on stamp-silence means a stranded `.md` is only surfaced once the agent stops, so healthy long turns are never prematurely resolved. Wired into both `_poll_sentinel_with_idle_detect` (the stalled/timeout exits now return `succeeded` if a fresh reply `.md` is present) and `_reconcile_ideas_session_after_late_done` (now heals a `pending` placeholder, not just `error`, and accepts a stranded `.md` via the helper; `GET /session` passes `ideas_idle_threshold` as `quiet_secs`). Verified live: a `GET /session` on the stuck session-24 healed the placeholder from `pending` to the real "Number Blocker" reply. New tests: `tests/test_ideas_stranded_md_recovery.py` (9 — helper unit cases incl. the stamp-active negative, poll stalled→succeeded, reconcile pending→reply).

- **Ideas chat held one connection for the server's full 900 s patience → long replies hung / needed a refresh.** The chat send was a single blocking `fetch` with no client-side timeout, so after `poll_timeout` was raised to 900 s the browser held one HTTP connection for up to 15 minutes. The recovery poll that surfaces a reply without a refresh only started after an explicit 408/502/503 — which now doesn't fire until 900 s — so any long reply whose connection dropped or hung mid-wait left the spinner stuck until a manual refresh (the server had finished and written `session.json`, but nothing was watching). Fix (frontend, `ui/index.html`): the chat `fetch` is now bounded by an `AbortController` (`CLIENT_WAIT_MS = 120 s`); on abort **or** a network drop the handler keeps the "Working on your request…" bubble (no error, no draft-restore — the server is still working) and hands off to a recovery poll that watches `GET /api/ideas/{id}/session` until the turn's assistant message is non-pending (a real reply **or** the server-written reason-aware error), covering the full 900 s backstop (`maxTicks: 192`) and bailing fast (~30 s) if the server is actually unreachable. The reason-aware timeout messages still reach the user — the recovery poll reads the placeholder the server writes on its 408. **One shared `startSessionHealPoll` helper** now serves both the 408 late-heal (`resolveWhen` = no assistant error remains) and the abort/network recovery (`resolveWhen` = assistant no longer pending) — the previous inline late-heal `setInterval` was removed so there is a single session-poll loop (dual-source guard). Server `poll_timeout` stays 900 s (the server keeps working; the client just stops *holding* the line). ### Fixed

- **Escalation NameError crash (`_PIPELINE_ARTIFACTS` → `PROJECT_ARTIFACTS_DIR`):** `orchestrator.py` referenced the undefined name `_PIPELINE_ARTIFACTS` at two points in the escalation webhook message construction (repo-init-failure path line 2862 and blame-cap path line 4132). Both occurrences replaced with the correct module-level constant `PROJECT_ARTIFACTS_DIR`. `webhook_client.py`'s own `_PIPELINE_ARTIFACTS` (the workspace-relative agent-facing path string) is unchanged.

- **`ERR_UNACCOUNTED_DELETION` false positive on vite content-hash bundle rotation:** `executor_gate.py` now distinguishes vite content-hashed build artifact rotation from genuine unaccounted file deletion. Files under `dist/assets/` matching the pattern `*-{6–12 alphanum chars}.{js|css}` are auto-accounted when the parent directory still contains at least one file with the same extension after the build (proving rotation, not wipe). A `[GATE WARN]` line is emitted to stderr listing the auto-accounted paths; the gate passes. All other deletion checks — source files, non-hash-named dist files, wipes with no replacement — behave identically to before. This eliminates the systematic failure loop that caused GAME-E1, DATA-E3, and UI-E4 to exhaust executor retries whenever a phase ran `npm run build` as part of test verification.

- **`_ideas_scrub_stale_turn_artifacts` tolerance gap:** The scrub now uses the same `IDEAS_LATE_DONE_MTIME_SLACK_SEC` (2 s) boundary as `_late_done_valid_for_attempt` when deciding whether to delete a prior `turns/{n}.done` sentinel. Previously, a `.done` written just before `attempt_start_wall` could be removed after the webhook POST but before the poll, causing spurious `408` responses from `POST /api/ideas/{id}/message`.

- **Inference provider rejections (`ERR_PROVIDER_REJECTED`):** Renamed `ERR_PROVIDER_QUOTA` to `ERR_PROVIDER_REJECTED` for clearer operator-facing semantics. The orchestrator now re-reads session JSONL after planner and reviewer gate failures (in addition to post-poll paths) so late-flushed OpenRouter-style billing/auth errors escalate immediately without burning agent retry budget; reviewer paths now call the same detection as planner/executor. The dashboard `LastErrorCode` chip shows an explicit title for `ERR_PROVIDER_REJECTED` and `ERR_SESSION_DEAD_ON_ARRIVAL`.

- **`GET /api/ideas/{id}/session` stale roadmap:** when `roadmap_draft.done` exists and `roadmap_draft.md` differs from `session.json` `roadmap_content` (regenerate wrote disk but session was not updated), rehydration now replaces session from disk so the Ideas Roadmap tab matches the converter output.

### Removed

- `AUTODEV_USE_LEGACY_OPENCLAW_RUNTIME` environment flag and `use_legacy_openclaw_runtime` UI config key. Both are silently ignored if they remain in stale `.env` / `config.json`. To reproduce the old behaviour, set `AUTODEV_PIPELINE_ROOT=$OPENCLAW_ROOT` explicitly. The flag's branching logic has been removed from `orchestrator.py`, `heartbeat_cron.py`, gate scripts, and `ui/server.py`.
- Legacy env-var aliases `AUTODEV_ROOT` and `AUTODEV_RUNTIME_ROOT` and the UI config alias `autodev_runtime_root`. The resolver functions in `autodev/pipeline/env_resolvers.py`, the `load_config()` layer in `ui/server.py`, the `_spawn_orchestrator` env builder (which now actively scrubs inherited legacy aliases), the `.env` writer in `install.sh`, and the pipeline module constants (`orchestrator.py`, `sentinel_poller.py`, `skill_manager.py`, `session_cleanup.py`, `heartbeat_cron.py`) have all been updated to read and emit only canonical names.
